# 需求分析文档

## 1. 业务背景

中小企业售后/运维场景中，产品手册、FAQ、历史工单、订单数据分散在 PDF、Word、Excel、聊天记录和业务系统中：

- 客服重复回答同一类问题，效率低
- 工单分派靠人工，错派、重派时有发生
- 知识更新慢，新人上手周期长
- 敏感数据无法直接调用公有云大模型

项目目标：构建一个基于 RAG + Agent 的企业售后知识库平台，实现智能问答、自动建单、自动派单、人工兜底。

## 2. 用户角色

| 角色 | 描述 | 主要入口 |
|---|---|---|
| 终端客户 | 报修、咨询、查订单 | 企业微信/飞书/钉钉/网页 |
| 客服人员 | 处理疑难问题，审核 AI 答案 | 客服工作台 |
| 运维工程师 | 接收并处理工单 | 工单系统/企业微信 |
| 知识库管理员 | 上传文档、审核回流 | Web 管理后台 |
| 系统管理员 | 监控、配置、审计 | 管理后台/API |

## 3. 功能需求

### 3.1 智能问答
- FR-1：用户提问，系统基于知识库返回带引用的答案
- FR-2：无依据时拒答，不编造
- FR-3：置信度低于阈值时自动转人工
- FR-4：支持多轮对话，保留槽位

### 3.2 工单自动化
- FR-5：用户确认报修后自动创建工单
- FR-6：自动填写设备型号、故障描述、联系人、地址
- FR-7：按故障类型/区域/技能自动派单
- FR-8：派单成功后通知工程师和客户
- FR-9：幂等控制，防重复建单

### 3.3 人工审批（HITL）
- FR-10：退款、改派等关键操作需人工审批
- FR-11：审批在对话中进行，用户不跳出当前渠道
- FR-12：审批通过后工作流自动恢复

### 3.4 知识管理
- FR-13：支持 PDF/Word/Excel/FAQ 上传
- FR-14：自动清洗、切片、向量化、入库
- FR-15：支持版本管理和权限过滤
- FR-16：人工修正后答案自动回流

### 3.5 评估与监控
- FR-17：RAGAS 自动评估检索与生成质量
- FR-18：LangSmith 链路追踪
- FR-19：Prometheus 指标暴露

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 响应延迟 | P95 < 5s（本地 Ollama），云端 API < 3s |
| 并发 | 单机支持 10 并发对话 |
| 隐私 | 敏感数据走本地模型，不出域 |
| 可用性 | 云端 API 异常时自动降级到本地 |
| 可观测 | 每次问答有 trace_id，可追溯 |
| 部署 | Docker Compose 一键启动 |

## 5. 验收标准

- 知识库 Top5 召回率 >= 85%
- RAGAS faithfulness >= 0.85
- 工单分派准确率 >= 90%
- 平均响应时间 < 10s（1060 本地推理）
- 低置信度转人工率可配置

## 6. 风险与约束

| 风险 | 应对 |
|---|---|
| 1060 显存不足 | 用 Q4 量化 + 小模型 + 云端兜底 |
| vLLM 不支持 Pascal | 用 Ollama 替代 |
| Bridge 插件仅验证 Slack | 用飞书先验证，必要时适配 |
| RAG 幻觉 | 强制引用 + 拒答 + RAGAS 评估 |
| 文档质量差 | 父子块切片 + 表格转 Markdown |
